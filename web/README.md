# MIMIC Web（React + TypeScript）

廠務燈號平台的桌機版網頁設計。燈號：🔴 紅＝異常、🟡 黃＝部分異常、🟢 綠＝正常、⚪ 灰＝無資料；資料來源為 FDM（目前以模擬資料取代）。

```bash
cd web
npm install
npm run dev        # http://localhost:5173
npm test           # 燈號判定邏輯單元測試（vitest）
npm run build      # tsc 型別檢查 + 正式建置到 dist/
```

## 兩層架構

```
戰情指揮官層（全廠總覽、自建指揮頁）     巨觀與指揮值班
  每顆燈 = 一個值班情境頁，取該頁最差燈號
  點燈號 → 進入值班情境的 MIMIC（不下鑽）
        │
值班情境層（Power、UPW、HVAC…、自建值班頁）
  每顆燈 = 一個 virtual tag，值就是燈號代碼
  點燈號 → 下鑽層：由 virtual tag 讀回 InSQL tag 清單（數值、OOC、OOS）
```

- **值班情境**：和原本的 MIMIC 相同，是燈號與文字積木組成的畫布。燈號綁上游定義的 **virtual tag**，判定在上游完成，MIMIC 不重算。
- **戰情指揮官**：由值班情境組成。燈號取該值班情境頁所有燈號最差（紅 > 黃 > 灰 > 綠，有缺資料不報平安），文字顯示各色數量（例如「1 紅 · 1 黃」）。只能引用值班情境頁，不會一層套一層。
- 指揮官層目前只做燈號；值班人員、異常確認、交辦事項等指揮功能之後再加。

### virtual tag 燈號代碼

| virtual tag 的值 | 燈號 |
|---|---|
| 2 | 紅 |
| 1 | 黃 |
| 0 | 綠 |
| 沒有值、或不在表上 | 灰 |

對照表在 `src/lib/status.ts` 的 `LAMP_CODE`，要改代碼只改這裡。

### 積木

使用者看到的主要呈現都是積木，內建頁面與自建頁面共用同一套（架構與擴充方式見 [`src/blocks/README.md`](src/blocks/README.md)）：

| 積木 | 層級 | 用途 |
|---|---|---|
| 燈號 | 值班情境 | 綁一個 virtual tag，值就是燈號；點了下鑽 InSQL tag 清單 |
| 值班情境燈號 | 戰情指揮官 | 代表一個值班情境頁，取該頁最差燈號；點了進入該頁。用關鍵字 + System + Phase 搜尋要引用的值班情境頁 |
| 文字 | 兩層都可用 | 標題與備註 |

每個積木都有**小 / 中 / 大**三種尺寸，長寬比例 **1 : 2 : 4**。燈號類積木：**小**只有一顆燈（沒有外框與文字，名稱與狀態在滑鼠提示）、**中** 96 × 88（燈號 + 一行字）、**大** 192 × 176（名稱 + 燈號 + 一行字）。尺寸改定義前存的頁面讀取時自動換算（原本的小 → 中、中 → 大、原本 384 × 352 的大已移除 → 大），畫面維持原樣。編輯模式下：**點一下積木選取**，工具列固定顯示在積木下方（尺寸切換、編輯、複製、刪除）；雙擊或按「編輯」開啟編輯器，右側以實際大小即時預覽。點空白處或按 Esc 取消選取。

### 燈號積木：選一個 virtual tag

燈號**不需要設定任何條件**。編輯器裡選廠區、輸入 virtual tag 名稱按「檢查並套用」（不分大小寫，上游找不到會提示），或從 virtual tag 清單搜尋點選；選取後顯示目前值與燈號。

舊資料會自動轉換：舊版「整個情境」的燈號轉成該廠區 × 系統的 virtual tag；舊版「選取 Tag」與自訂算式的燈號沒有對應的 virtual tag，顯示灰燈「尚未選擇 virtual tag」，需要重新選擇。

### 內建頁面也是積木

- **全廠總覽**（戰情指揮官）：每個內建值班情境（Power、UPW、HVAC、Exhaust、Gas、Chemical）一顆燈號，依尺寸分大、中、小三欄展示：超純水用大、電力與空調用中（下方顯示積木名稱）、其餘用小（只有燈，旁邊用文字積木標名稱）。每欄另有一個綠燈範例：F18P1 公用系統值班（大）、F18P2 大宗氣體值班（中）、UPW 停機演練看板（小），這三個值班情境目前全部正常。
- **南科戰情官總覽**（戰情指揮官，主管簡報用）：每個廠區一列（F18P1～P3），每列五顆大尺寸燈號：水（超純水）、電（電力）、空調（MAU）、氣體（大宗氣體）、化學供應（化學品），一個畫面看完。每顆燈代表一個值班情境頁，取該頁最差燈號，點了進入。側欄最上方的「★ 主管簡報」分類放著這一頁；已經有側欄設定的人也會自動加入一次（刪掉後不再加回）。
- **南科子系統值班情境**（15 頁，例如 F18P2 水系統值班）：每個子系統一顆大尺寸燈號（超純水：前處理、RO 逆滲透、EDI 混床、拋光、供水迴路；電力：變壓器 TR1／TR2、UPS、匯流排；空調：MAU 01～04；氣體：一般氮氣、純化氮氣、氬氣、氦氣；化學供應：HF、H₂SO₄、NH₄OH、IPA、HCl、SC1），綁上游的子系統 virtual tag（例如 `F18P2.UPW.POL.LAMP`），點了下鑽 InSQL tag。廠區沒有某組 Tag 時不放那顆燈。不另放「整體」燈號，避免指揮官層的燈號數量重複計算。
- **無塵室空調品質管理**（值班情境，地圖型 MIMIC）：底圖是 F18P2 3F 無塵室示意圖（Bay A～H、主走道、空調機房 MAU 01～04、柱位格線），每個 Bay 中央一顆小尺寸燈號，綁該 Bay 的溫度、濕度、室壓差、微粒數 virtual tag（例如 `F18P2.CR.BAYC.LAMP`）；每台 MAU 上一顆，綁 MAU 子系統 virtual tag。展示情境：MAU 03 送風溫度偏高（黃），它供氣的 Bay C 溫濕度超規（紅）、Bay G 偏高（黃）；Bay H 感測器離線（灰）。
- **純水廢水水平衡圖**（值班情境，拓樸型 MIMIC）：底圖是 F18P1 純水／廢水水平衡流程圖。上排是純水製造（自來水補水 → 原水池 → 前處理 → RO → EDI → 拋光 → 供水迴路 → Fab），下排是四股廢水（有機、酸鹼、研磨、含氟）；酸鹼與有機廢水經回收水回到原水池，研磨與含氟廢水處理後放流。邊上標設計流量（m³/h），收支平衡：補水 600 ＝ 放流 520 ＋ 損耗 80，回收 400 ／ 用水 1,000（回收率 40%）。13 個處理單元各一顆小尺寸燈號：純水單元綁超純水子系統、廢水單元綁新的「廢水回收」子系統 virtual tag（例如 `F18P1.WW.FW.LAMP`）。「水平衡」燈號由補水量、損耗與差異率組成，差異率超過 5% 為黃、10% 為紅（流量本身只記錄、不判燈）。展示情境：含氟廢水 F⁻ 超標（紅）、水平衡差異 6.8%（黃），其餘正常。
- **台電入口至高壓迴路供應圖**（值班情境，單線圖型 MIMIC）：底圖是 F18P2 示意單線圖，由上而下：台電 161 kV 一回線、二回線 → 161 kV GIS 受電站 → 主變壓器 MTR-1／MTR-2（161/22.8 kV）→ 22.8 kV Bus A／Bus B（中間聯絡斷路器常開）→ 高壓迴路一／二（開環運轉，中間常開點）→ 次變電站 SS-1～SS-4（Fab 黃光、Fab 蝕刻、CUB 冰水主機、UPW／廢水）；緊急發電機併 Bus B。15 個設備各一顆小尺寸燈號，綁新的「高壓電力」子系統 virtual tag（例如 `F18P2.HV.MTR1.LAMP`）：電壓、頻率、SF₆ 氣壓、局部放電、負載率、溫度、斷路器狀態（應閉合的開啟＝紅；常開的聯絡斷路器閉合＝黃）、發電機待機與油位。展示情境：台電二回線電壓偏低（黃），聯絡斷路器閉合改由 MTR-1 供兩段匯流排（黃，MTR-1 負載升到 78%），SS-3 變壓器過溫（紅）。

### 複製頁面（Duplicate）

任何積木畫布頁（內建、Explore、自建）在檢視模式按 **Duplicate**，複製成自己的新頁面，建立後直接進入編輯模式。

- **複本是獨立頁面**：積木深拷貝，之後修改互不影響；層級、燈號的 virtual tag 綁定、底圖（可勾選）一起複製。頁首顯示「複製自 原頁面」。
- **燈號換廠區**（選填）：例如 F18P2 → F18P3。燈號改綁新廠區的同名 virtual tag（`F18P2.UPW.POL.LAMP` → `F18P3.UPW.POL.LAMP`），積木名稱、文字與頁面名稱裡的廠區一併替換，Phase 自動改成新廠區。新廠區沒有對應 tag 的燈號會清空綁定並列出，避免 F18P3 的頁面顯示 F18P2 的燈號。多廠區的頁面可選要換哪一個廠區。
- **名稱、System、Phase、分類**：預設沿用原頁面（名稱加「（複本）」）；原頁面跨多個系統或廠區時需要自己選。
- **指揮官頁**：燈號仍指向原本的值班情境頁，要連到新的值班頁請在複本裡逐一改選。

### 底圖（地圖型 MIMIC）

編輯模式左側積木庫下方的「底圖」區可以**上傳圖檔**（PNG、JPG、SVG、WebP，展示版 1.5 MB 以內）或**套用範本**（無塵室示意圖、水平衡拓樸圖、高壓單線圖），並調整**底圖透明度**、更換或移除。

- 有底圖時，畫布大小等於底圖，積木座標以底圖像素為準；檢視、編輯與全螢幕時，圖和燈號一起縮放到畫面寬度，換螢幕燈號也不會跑位。拖曳距離會依縮放倍率換算回底圖座標。
- 底圖存在頁面資料的 `background`：`{ src, width, height, name, opacity }`。`src` 是上傳圖檔的 data URL，或內建範本的 `builtin:<id>`。正式環境應改存後端並控管權限（平面圖屬機密），頁面只記圖檔編號。
- 上傳的圖以 `<img>` 顯示，SVG 裡的程式碼不會執行。
- 移除底圖後回到一般畫布，積木保留。
- **各系統頁與 Explore 的頁面**（值班情境）：每個廠區 × 系統一顆小燈號，綁該格的 virtual tag；欄名、列名、標題是文字積木。

按 **Edit** 就能像自建頁面一樣拖曳、縮放、增刪，修改自動儲存；要回到原樣請用頂欄「?」裡的**重置展示資料**（會一併重置所有頁面與側欄）。內建頁面的層級改變時（例如全廠總覽改為戰情指揮官），之前存下的舊版面不再使用，改用新的預設版面。

### 自建頁面

- 側欄「＋ 新增頁面」（或各分類標題的 ＋）建立空白頁面，先選**層級**（值班情境 / 戰情指揮官），並必填 **System**（6 個系統或「全系統」）與 **Phase**（F18P1/P2/P3/P7 或 F18A 全廠），再進入畫布編輯模式（`/p/u-xxxxxx/edit`）。System · Phase 顯示在頁首，編輯模式可修改。
- 左側**積木庫**依層級列出可用的積木，點一下加到畫布；積木可拖曳（對齊 10px 格線）、方向鍵微調、複製、刪除。

### 側欄

- 預設側欄展示「我的最愛當專案清單」的用法：① UPW 擴充專案、② MAU 節能專案、③ 日常值班，分類即專案、編號即優先順位。
- 戰情指揮官頁在側欄標示「指揮」。
- Favorites 旁的 ＋ 是**新增分類**；分類可改名、刪除（頁面會併入相鄰分類，不會消失）。
- **所有頁面（含內建頁面）都能上下調整**：拖曳到任何分類的任何位置，或用滑過時出現的 ↑ ↓ 按鈕（到分類邊界會跨到相鄰分類）。分類本身也能拖曳或用 ↑ ↓ 調整順序。

左側 Favorites 側欄可收合為窄欄、群組可展開 / 收起、群組內可拖曳排序；狀態存在 localStorage。**Full screen** 進入看板模式（Esc 離開）。

## FDM 取值時機

- **燈號**：只在開啟網頁時一次、按重新整理時一次（頂欄更新時間旁的按鈕、下鑽頁的 Refresh Values），不做定時自動更新。只取所有頁面燈號用到的 virtual tag，去除重複後**合成一次批次請求**（`fetchLamps`），所有頁面與積木共用這份結果。
- **下鑽**：進入下鑽頁時，才由那個 virtual tag 讀回 InSQL tag 清單（`fetchVTagDetail`，一次請求），暫存到下次按重新整理。
- **新選的 virtual tag**：在燈號編輯器選了還沒取過值的 virtual tag 時，只查這一個並併入目前的資料。
- 指揮官燈號不另外取值，直接用值班情境頁裡的 virtual tag 結果。
- 正式環境建議由 MIMIC 後端統一向 FDM 取值並暫存，不論多少使用者，FDM 每次只被呼叫一次。

## 燈號判定規則

- **值班燈號**：virtual tag 的值就是燈號代碼（見上表），前端不做門檻判斷。
- **下鑽的 InSQL tag**：沒有資料 → 灰；`isOOS` → 紅；`isOOC` → 黃；否則綠。
- **指揮官燈號、頁面燈號**：取最差，紅 > 黃 > 灰 > 綠，有缺資料的頁面不報平安。

## 結構

```
src/catalog/catalog.ts  廠區、系統、模擬資料用的 InSQL tag、頁面目錄（含 Explore 資料與層級）

src/lib/status.ts       燈號代碼對照、InSQL tag 判定、彙整、規則文字（純函式，有測試）
src/lib/blocks.ts       燈號積木綁的 virtual tag 與判定（有測試）
src/lib/pages.ts        頁面層級、指揮官看值班情境的彙整、要取值的 virtual tag（有測試）
src/blocks/             積木：lamp（燈號）、duty（值班情境燈號）、text（文字），以及內建頁面的預設版面
src/state/              FDM / 頁面 / Favorites / UI 的 Context
src/pages/              UserPageView、LampDrillPage（下鑽）、VTagsPage、ExplorePage、PageRoute、EditRoute
src/components/         Layout、Sidebar、Topbar、Lamp、LayerChip 等
```
