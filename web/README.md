# MIMIC Web（React + TypeScript）

廠務燈號平台的桌機版網頁設計。燈號：🔴 紅＝異常、🟡 黃＝部分異常、🟢 綠＝正常、⚪ 灰＝無資料；資料來源為 FDM（目前以模擬資料取代）。

```bash
cd web
npm install
npm run dev        # http://localhost:5173
npm test           # 燈號判定邏輯單元測試（vitest）
npm run build      # tsc 型別檢查 + 正式建置到 dist/
```

## 頁面與網址

每一頁都有獨立網址（BrowserRouter；正式部署的靜態伺服器需把所有路徑 fallback 到 `index.html`）。

| 網址 | 內容 |
|---|---|
| `/p/overview` | 首頁燈號牆：由「燈號」與「文字」積木組成的畫布（每個廠區 × 系統是一顆系統燈號積木），點燈號下鑽 |
| `/p/:slug/:site/:system` | 下鑽頁：規則說明、Tag name / Description / Value，可切「僅顯示異常 / 全部 Tag」，Refresh Values 重新取值 |
| `/p/:slug/edit` | 編輯模式：積木畫布（左側積木庫）。自建頁面與內建燈號牆頁面共用；內建頁面可「還原預設版面」 |
| `/explore?q=UPW&system=…&site=…&author=…&sort=…` | 搜尋他人頁面、篩選、排序；☆ 加入 / 移除 Favorites（搜尋條件放在網址，可分享） |
| `/p/:slug` | 其他頁面（Favorites 側欄、Explore 結果）；單一廠區 × 系統的頁面直接顯示下鑽內容 |

### 積木

使用者看到的主要呈現都是積木，內建頁面與自建頁面共用同一套（架構與擴充方式見 [`src/blocks/README.md`](src/blocks/README.md)）：

| 積木 | 用途 |
|---|---|
| 燈號 | 挑 Tag、用算式決定紅 / 黃 / 綠，顯示一顆燈（單顆燈 + 下方一行文字） |
| 文字 | 標題與備註 |
| 燈號牆、系統摘要、Tag 清單 | 目前只用來組成內建下鑽頁，積木庫暫不開放 |

每個積木都有**小 / 中 / 大**三種尺寸，長寬比例 **1 : 2 : 4**。編輯模式下：**點一下積木選取**，工具列固定顯示在積木下方（尺寸切換、編輯、複製、刪除），積木左上角標示目前尺寸；雙擊或按「編輯」開啟編輯器，右側以實際大小即時預覽。點空白處或按 Esc 取消選取。

### 內建燈號牆也是積木

全廠總覽與各系統頁（Power、UPW、HVAC…）都是由「燈號」與「文字」積木組成的畫布：每個廠區 × 系統是一顆**系統燈號**（小尺寸，顯示「3 台異常」，點了下鑽），欄名、列名、標題是文字積木。按 **Edit** 就能像自建頁面一樣拖曳、縮放、增刪，修改自動儲存；**還原預設版面**可回到原樣。

燈號積木的**資料來源**有兩種：

- **系統燈號**：選廠區與系統，沿用平台的紅、黃、綠判定規則（門檻目前使用 `catalog.ts` 的預設值，暫無設定畫面）。
- **自訂算式**：自己挑 Tag、寫算式（見下）。

### 自建頁面

- 側欄「＋ 新增頁面」（或各分類標題的 ＋）建立空白頁面，進入畫布編輯模式（`/p/u-xxxxxx/edit`）。
- 左側**積木庫**列出所有積木種類，點一下加到畫布；積木可拖曳（對齊 10px 格線）、方向鍵微調、複製、刪除。
- **燈號積木**的編輯器：
  1. **資料點**：從所有廠區的 Tag 搜尋挑選，自動命名為 A、B、C…；每個資料點旁可填**模擬值**（或模擬無資料）試算燈號，只在編輯視窗內有效、不會存檔。
  2. **燈號條件**：紅燈條件、黃燈條件各寫一個算式，由上往下第一個成立的亮燈，都不成立亮綠燈。不想手寫可用**條件精靈**（填門檻數字，自動產生算式），或一鍵帶入系統預設門檻。
  3. **顯示值**（選填）：燈下方顯示的數字，例如 `(A + B) / 2`。
  4. **燈號文字**：數值優先 / 只顯示狀態文字 / 數值＋狀態；可自訂紅、黃、綠的狀態文字（預設：異常、部分異常、正常）。
  - 編輯器頂端的**檢查提醒**會指出沒選 Tag、沒用到的資料點、紅黃條件相同等問題。
- 算式支援 `+ − × ÷`（`+ - * /`）、括號、`> ≥ < ≤ = ≠`、`and / or / not`（也可寫 且 / 或 / 非 / && / || / !）、`abs min max avg round`。
- 即時預覽會把目前數值代入算式（例如 `3.4 > 3 or 17.4 < 17.5 → 成立`），說明為什麼亮這顆燈。
- 資料點無資料、尚未設定條件、算式有誤時，燈號為灰並顯示原因。
- 側欄該頁的圓點 = 頁面上所有有燈號意義的積木取最差。

### 側欄

- Favorites 旁的 ＋ 是**新增分類**；分類可改名、刪除（頁面會併入相鄰分類，不會消失）。
- **所有頁面（含內建頁面）都能上下調整**：拖曳到任何分類的任何位置，或用滑過時出現的 ↑ ↓ 按鈕（到分類邊界會跨到相鄰分類）。分類本身也能拖曳或用 ↑ ↓ 調整順序。

左側 Favorites 側欄可收合為窄欄、群組可展開 / 收起、群組內可拖曳排序；狀態存在 localStorage。燈號牆頁的 **Full screen** 進入看板模式（Esc 離開）。

## 燈號判定規則

- 單一 Tag：最新值為 null → 灰；最近 N 點**全部**超出紅色管制 → 紅；最新值超出黃色管制（或超出紅色但未連續 N 點）→ 黃；否則綠。
- 廠區 × 系統：任一 Tag 紅 → 紅；否則任一黃 → 黃；否則有綠 → 綠；全部無資料 → 灰。
- 頁面（側欄 / Explore 的圓點）彙整多個格子：紅 > 黃 > 灰 > 綠，有缺資料的頁面不報平安。
- 門檻依「系統 × 量測類型」設定（Tag 名稱 `.` 後的尾碼，如 `.TOC`、`.RES`），同系統所有廠區共用；留空代表不管制。

## 結構

```
src/catalog/catalog.ts    廠區、系統、量測類型門檻預設值、Tag 清單、頁面目錄（含 Explore 資料）
src/lib/fdm.ts          FDM 資料來源（模擬）。接真實 API 只需替換 fetchSnapshot
src/lib/status.ts       燈號判定、彙整、規則文字、門檻驗證（純函式，有測試）
src/state/              FDM / 門檻 / Favorites / UI 的 Context
src/pages/              WallPage、DrillPage、EditPage、ExplorePage、PageRoute
src/components/         Layout、Sidebar、Topbar、Lamp 等
```

示範資料內建幾個情境：F18P2 超純水 3 紅 2 黃 1 灰、F18P7 排氣整區無資料（灰）、F18P1 電力有一點尖峰值但未連續 3 點（黃）——在編輯模式把「連續成立點數」改成 1 再按 Test 就會看到它變紅。
